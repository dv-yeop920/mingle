## 이슈 1: OG 이미지 TTF 폰트 누락 (크리티컬) — 해결

### 증상

OG 이미지 요청 시 `ENOENT` 에러로 500 응답 발생. SNS 공유 시 OG 이미지가 깨짐.

### 원인

`perf: 폰트 TTF→woff2 변환으로 11MB→1.2MB 감소` 커밋(9068f89)에서 모든 TTF 파일을 삭제하고 woff2로 변환했으나, `src/app/opengraph-image.tsx:20`에서 `gothic-a1-800.ttf`를 `readFile`로 직접 읽고 있었다. Satori(next/og 내부 렌더러)는 TTF/OTF만 지원하므로 woff2로 대체 불가.

### 해결

```bash
git show 9068f89^:src/app/fonts/gothic-a1-800.ttf > src/app/fonts/gothic-a1-800.ttf
```

삭제 직전 커밋에서 `gothic-a1-800.ttf` (2.2MB)를 복구했다. 이 파일은 OG 이미지 및 PWA 아이콘 전용으로만 유지하며, 브라우저 폰트는 woff2를 계속 사용한다.

### 교훈

폰트 포맷 변환 시 서버 사이드에서 원본 포맷을 직접 읽는 코드가 있는지 반드시 확인해야 한다. `grep -r "\.ttf" src/`로 참조를 검색하면 누락을 방지할 수 있다.

### 관련 파일

- `src/app/opengraph-image.tsx` (폰트 로드)
- `src/app/icon.tsx` (PWA 아이콘 — 동일 폰트 사용)
- `src/app/apple-icon.tsx` (Apple Touch Icon — 동일 폰트 사용)
- `src/app/fonts/gothic-a1-800.ttf` (복구된 폰트)

## 이슈 2: Vitest ESM 설정 불일치 — 해결

### 증상

`vitest run` 실행 시 `ERR_REQUIRE_ESM` 에러 발생. `@vitejs/plugin-react` v6.x를 `require()`로 로드하려 해서 실패. 35개 테스트 파일 실행 불가.

### 원인

`@vitejs/plugin-react` v6과 Vitest 4.x는 ESM-only 패키지로 전환되었지만, `package.json`에 `"type": "module"`이 없어 Node.js가 CJS 모드로 `vitest.config.ts`를 처리했다.

### 해결

두 가지 변경을 적용했다.

**1단계: `package.json`에 `"type": "module"` 추가**

```json
{
  "type": "module"
}
```

이것만으로는 jsdom 30.x의 의존성 체인 내 CJS/ESM 충돌이 발생했다. `html-encoding-sniffer`가 ESM-only인 `@exodus/bytes`를 `require()`로 로드하려 해서 동일한 `ERR_REQUIRE_ESM` 에러가 다른 위치에서 발생.

**2단계: jsdom → happy-dom 전환**

```ts
// vitest.config.ts
test: {
  environment: 'happy-dom',  // 기존: 'jsdom'
}
```

`happy-dom`은 ESM 네이티브 DOM 구현체로, CJS 의존성 충돌 없이 동작한다. `jsdom` 제거 후 `happy-dom` 설치.

### 결과

```text
Test Files  35 passed (35)
Tests      187 passed (187)
Duration   6.54s
```

### 교훈

- ESM-only 패키지 도입 시 의존성 트리 전체의 CJS/ESM 호환성을 확인해야 한다.
- `jsdom`은 내부 의존성(`html-encoding-sniffer` → `@exodus/bytes`)이 CJS/ESM 혼합이므로 `"type": "module"` 환경에서 충돌할 수 있다.
- `happy-dom`은 더 가볍고 ESM 호환성이 좋으며, 테스트 속도도 유사하거나 빠르다.

### 관련 파일

- `package.json` (`"type": "module"` 추가, `jsdom` → `happy-dom`)
- `vitest.config.ts` (environment 변경)

## 이슈 3: 로그인 페이지 Next.js 16 프리렌더링 경고 — 해결

### 증상

E2E 테스트에서 `/login` 페이지 접근 시 콘솔에 Next.js 16 프리렌더링 경고 발생. `searchParams`가 `<Suspense>` 밖에서 await됨.

### 원인

`src/app/(auth)/login/page.tsx`에서 `searchParams` Promise를 최상위에서 await하면 Next.js 16이 해당 페이지를 정적으로 프리렌더링하려다 Request-time API를 만나 경고를 발생시킨다. `searchParams`는 Request-time API로, `<Suspense>` 경계 안에 있어야 정적 셸과 동적 콘텐츠가 분리된다.

### 해결

`searchParams` await 로직을 별도 async 컴포넌트로 분리하고 `<Suspense>`로 감쌌다.

```tsx
// Before (경고 발생)
const LoginPage = async ({ searchParams }: LoginPageProps) => {
  const { redirect } = await searchParams;
  const redirectTo = redirect === '/result' ? redirect : undefined;
  return <LoginView redirectTo={redirectTo} />;
};

// After (정적 셸 + 동적 콘텐츠 분리)
const LoginContent = async ({ searchParams }: LoginSearchParams) => {
  const { redirect } = await searchParams;
  const redirectTo = redirect === '/result' ? redirect : undefined;
  return <LoginView redirectTo={redirectTo} />;
};

const LoginPage = ({ searchParams }: LoginSearchParams) => (
  <Suspense>
    <LoginContent searchParams={searchParams} />
  </Suspense>
);
```

### 교훈

Next.js 16에서 `searchParams`, `cookies()`, `headers()` 등 Request-time API를 사용하는 페이지는 반드시 Suspense 경계로 동적 부분을 감싸야 한다. 이렇게 하면 페이지의 정적 셸은 프리렌더링하고, 동적 부분만 요청 시 렌더링한다.

### 관련 파일

- `src/app/(auth)/login/page.tsx`

## 이슈 4: PWA 아이콘 부족 — 해결

### 증상

`manifest.ts`에 `favicon.ico`만 선언되어 있어 PWA 설치 시 아이콘이 없고, iOS 홈 화면 북마크 시 기본 스크린샷이 사용된다.

### 원인

`manifest.ts`의 `icons` 배열에 `{ src: '/favicon.ico', sizes: 'any' }`만 존재. PWA 표준에서 요구하는 512×512 PNG 아이콘과 apple-touch-icon이 없다.

### 해결

Next.js 메타데이터 파일 컨벤션을 활용해 동적 아이콘 생성 파일을 추가했다.

**1. `src/app/icon.tsx` (512×512 PWA 아이콘)**

`ImageResponse`(Satori)를 사용해 브랜드 컬러(`BRAND_BACKGROUND_COLOR`, `BRAND_DEEP_COLOR`) 배경 위에 "M" 글자를 렌더링하는 512×512 PNG를 동적 생성한다. Next.js가 자동으로 HTML `<link rel="icon">`에 추가한다.

**2. `src/app/apple-icon.tsx` (180×180 Apple Touch Icon)**

동일한 디자인으로 180×180 사이즈의 apple-touch-icon을 생성한다. Next.js가 자동으로 HTML `<link rel="apple-touch-icon">`에 추가한다.

**3. `manifest.ts` icons 배열 업데이트**

```ts
icons: [
  { src: '/favicon.ico', sizes: 'any', type: 'image/x-icon' },
  { src: '/icon', sizes: '512x512', type: 'image/png' },
],
```

### 관련 파일

- `src/app/icon.tsx` (신규)
- `src/app/apple-icon.tsx` (신규)
- `src/app/manifest.ts` (수정)
