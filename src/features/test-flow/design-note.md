# Test Flow Profile Prefill

## 분석 결과 세션 복구

### 1. 요구사항과 상태 전이

- 게스트 분석이 완료되면 결과 전체를 같은 탭의 `sessionStorage`에 저장한다.
- 결과 메인·분위기·역할·전체 페어·페어 상세 화면을 새로고침해도 같은 결과를 복원한다.
- 결과 저장 성공이나 다시 테스트하기로 메모리 결과를 비우면 세션 결과도 함께 삭제한다.
- `/result` 하위 화면 밖으로 이동하면 저장하지 않은 메모리·세션 결과를 함께 삭제한다.
- 저장 버튼에서 로그인·회원가입으로 이동하는 동안은 저장 흐름을 이어갈 수 있도록 결과를 유지한다.
- 손상된 JSON이나 현재 스키마와 맞지 않는 이전 결과는 복원하지 않고 제거한다.

### 2. 런타임 흐름

- 루트 Provider의 `AnalysisResultSessionManager`가 앱 최초 hydration 때 세션 결과를 Zustand에 복원한다.
- 저장을 위해 `/login`·`/signup?redirect=/result`로 이동하면 복원 완료 상태를 잠시 해제하고, 인증 후 `/result` 복귀 시 세션 결과를 다시 확인한 뒤 완료 처리한다.
- 경로와 쿼리 문자열을 함께 구독해 인증용 `redirect` 유무가 바뀌는 경우도 같은 결과 흐름인지 정확히 판별한다.
- 복구가 끝나기 전 결과 화면은 로딩 상태를 유지해 빈 결과가 먼저 보이는 깜빡임을 막는다.
- 인증 화면에 머무는 동안 메모리 결과가 일시적으로 비워져도 세션 스냅샷은 삭제하지 않아 로그인 완료 후 복구할 수 있다.
- 이후 Zustand의 `analysisResult` 변경만 구독해 분석 완료 직후 저장하고, `null` 전환 시 삭제한다.
- `usePathname()`으로 직전 경로와 현재 경로를 비교해 결과 상세 간 이동과 실제 결과 영역 이탈을 구분한다.

### 3. 데이터 설계

- OpenAI 응답 스키마에 결과 화면용 `members`, `groupType`, `customName`을 합친 스냅샷만 저장한다.
- `schemaVersion: 1`과 Zod 검증을 저장소 경계에 두어 데이터 구조 변경 시 안전하게 폐기할 수 있다.
- 로그인 후 DB에 저장된 결과는 URL의 분석 ID와 React Query가 원본이므로 세션 스냅샷에 중복 저장하지 않는다.

### 4. UI와 접근성

- 기존 결과 UI와 인터랙션은 바꾸지 않고 복구 중에는 기존 로딩 문구를 사용한다.
- 저장소 접근이 실패해도 분석 직후의 메모리 결과는 계속 사용할 수 있다.

### 5. 성능과 운영

- 네트워크 재분석 없이 작은 JSON 스냅샷을 앱 시작 시 한 번 읽고 결과 변경 시에만 쓴다.
- 결과 스키마, 저장소 유틸, 복구 매니저를 분리해 저장 실패와 렌더링 실패를 독립적으로 테스트할 수 있다.

## 멤버 입력 세션 초안

### 1. 요구사항과 상태 전이

- `/members`에서 닉네임·MBTI·성별을 수정하거나 멤버를 추가/삭제하면 현재 초안을 같은 탭의 `sessionStorage`에 저장한다.
- 브라우저 새로고침 뒤에는 저장된 초안을 복원한다.
- `/members`에서 다른 경로로 이동하면 세션 초안을 삭제한다. 분석 요청에 필요한 Zustand 메모리 상태는 그대로 유지한다.
- 빈 닉네임 같은 작성 중 상태는 저장하되, 손상된 JSON·허용되지 않은 타입·인원수 불일치는 복원하지 않는다.

### 2. 런타임 흐름

- 루트 Provider 아래의 `MemberDraftSessionManager`가 `usePathname()`으로 현재 경로와 직전 경로를 비교한다.
- 앱이 `/members`에서 처음 마운트되면 현재 메모리 초안을 우선하고, 메모리가 비어 있을 때만 Zod 검증을 통과한 세션 초안을 Zustand에 복원한다.
- `/members`에 머무는 동안 Zustand를 동기 구독해 입력 직후 새로고침해도 마지막 변경을 저장한다.
- 클라이언트 라우팅으로 `/members`를 벗어난 경우에만 저장 키를 삭제하므로, 새로고침과 실제 이탈을 구분한다.

### 3. 데이터 설계

- 스냅샷은 `schemaVersion`, `groupType`, 현재 `members.length`, `members`만 보관한다.
- 분석 결과와 로딩 상태는 세션 저장 대상에서 제외해 오래된 결과가 복원되지 않게 한다.
- `memberDraftSchema`를 저장소 경계의 런타임 검증으로 사용하고, 잘못된 값은 즉시 삭제한다.

### 4. UI와 접근성

- 별도 UI를 추가하지 않고 기존 입력 컴포넌트 상태를 그대로 복원해 포커스 순서와 터치 영역에 영향을 주지 않는다.
- 저장소 접근 실패는 입력 흐름을 막지 않고 메모리 상태만으로 계속 사용할 수 있게 처리한다.

### 5. 성능과 운영

- 최대 15명의 작은 JSON만 입력 변경 시 동기 저장하며, 네트워크 요청과 새 의존성은 추가하지 않는다.
- 저장소 키를 기능 전용으로 분리해 스플래시 등 다른 세션 데이터와 충돌하지 않는다.
- 세션 유틸, Zustand 복원, 경로 이탈 삭제를 각각 테스트해 회귀 원인을 빠르게 구분할 수 있게 한다.

## 요구사항

- 비로그인 사용자는 기존처럼 MBTI 테스트를 수동 입력으로 이용할 수 있다.
- 로그인 사용자는 프로필의 닉네임, MBTI, 성별이 모두 있으면 첫 멤버를 "나"로 자동 초기화한다.
- 로그인 사용자에게 MBTI 또는 성별이 없으면 테스트 진입 전에 설정 화면으로 보내 보완시킨다.

## 흐름

- `/group-type`와 `/members` 라우트 컨테이너에서 서버 `fetchProfile()`을 호출한다.
- 프로필이 없으면 게스트로 간주하고 테스트 플로우를 차단하지 않는다.
- 프로필이 있지만 불완전하면 `/mypage/settings?required=profile&redirect=/group-type`로 redirect한다.
- 프로필이 완전하면 `convertProfileToSelfMemberSeed()`로 Zustand 초기화에 필요한 스냅샷만 만든다.
- 인원수 확정 시 `initializeMembers(count, selfMemberSeed)`를 호출하고 첫 멤버만 self seed로 채운다.

## 상태

- React Query와 서버 쿼리는 프로필 원본을 소유한다.
- Zustand는 테스트 중 사용할 멤버 스냅샷만 소유한다.
- 테스트 도중 프로필이 바뀌어도 이미 생성된 members는 유지하고, 다음 테스트부터 새 프로필을 반영한다.

## 예외

- 프로필의 MBTI 또는 성별이 허용된 union 값이 아니면 미설정으로 간주한다.
- 게스트 분석 결과를 로그인 후 저장할 수 있도록 guest result members에도 gender를 보존한다.
