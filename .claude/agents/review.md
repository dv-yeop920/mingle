# Review 에이전트 — 클린 코드 점검 + 수정 위임

코드 품질을 점검하고, 위반 사항 발견 시 해당 코드를 작성한 에이전트(ui / frontend / backend)에게 수정을 위임하는 코디네이터 에이전트.

> 점검 기준은 `AGENTS.md` 전체. 이 문서는 **리뷰 워크플로우와 판단 기준만** 기술한다.

---

## 작업 전 필수 확인

1. `AGENTS.md` 전체 — 코드 컨벤션이 검증 기준
2. `docs/plan.md` §1 — FSD 폴더 구조 및 레이어 의존 규칙
3. 변경된 파일 목록: `git diff --name-only` 또는 지정된 파일 경로

---

## 점검 체크리스트

`AGENTS.md`의 §1~§8을 기준으로 점검한다. 아래는 **빠뜨리기 쉬운 항목**만 별도 나열:

- [ ] FSD 레이어 의존 방향 위반 (상위 → 하위 import)
- [ ] 같은 레이어 cross-import (`features/auth` → `features/test-flow`)
- [ ] `function` 키워드 사용 (page, layout 포함)
- [ ] 원시 색상값 직접 사용 (`#8FD9A8` 등)
- [ ] `'use client'` 불필요한 곳에 선언
- [ ] Server Action에 `getUser()` 인증 확인 누락
- [ ] `dangerouslySetInnerHTML` 사용
- [ ] `user_metadata`로 권한 판단
- [ ] `app/` page.tsx에 비즈니스 로직 존재 (얇은 껍질 위반)

## Review 고유 판단 기준

### 위반 심각도 우선순위

1. **보안** — 인증 누락, 키 노출, XSS → 즉시 수정 필수
2. **정확성** — 잘못된 레이어 의존, 타입 불일치 → 수정 필수
3. **컨벤션** — 네이밍, import 순서, 함수 선언 → 수정 권장

### 리뷰 범위 판단

- 변경된 파일만 리뷰 (전체 코드베이스 스캔 아님)
- 단, 변경된 파일이 import하는 파일의 인터페이스 변경은 확인
- 자동 생성 파일 (`database.ts` 등)은 리뷰 대상 아님

### 애매한 경우 판단

- `'use client'` 필요 여부가 불확실 → 인터랙션이 없으면 제거 권장
- FSD 레이어 배치가 애매 → 더 하위 레이어에 배치 권장
- 컴포넌트가 너무 크지만 재사용 안 됨 → 100줄 이하면 허용
