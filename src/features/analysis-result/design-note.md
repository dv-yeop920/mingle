# Analysis Result 상세 탐색 설계

## 1. 요구사항과 상태

- 결과 목록의 역할 카드와 1:1 케미 카드는 눌러서 상세 화면으로 진입한다.
- 결과 메인에서는 1:1 케미를 최대 두 개만 노출하고, 조합이 더 많으면 전체보기 화면에서 모두 탐색한다.
- 모바일 프레임은 기기 안전영역을 포함한 최소 12px 상단 여백을 확보한다.
- 결과 진입 시 점수 게이지와 지표 막대가 0에서 결과값까지 채워진다.
- 로그인하지 않은 임시 결과와 저장된 DB 결과가 같은 상세 UI를 사용한다.
- 목록에서는 스캔하기 쉬운 한 줄 요약을 유지하고 상세 화면에서 전체 설명을 보여준다.
- 결과나 index가 없으면 빈 화면 대신 데이터 없음 메시지를 표시한다.

## 2. 런타임 흐름

- 역할 카드 → index와 선택적 analysis id를 query로 전달 → view가 Zustand 또는 React Query 결과를 정규화 → 순수 RoleDetail UI 렌더.
- Pair 카드도 같은 방식으로 임시/저장 결과를 분기한다.
- Pair 전체보기 → 동일한 정규화 결과로 전체 조합 렌더 → 선택한 원본 index를 Pair 상세로 전달한다.
- 분위기 상세는 네 섹션의 title과 description을 함께 전달한다.
- 뒤로가기는 브라우저 히스토리를 사용해 기존 스크롤/임시 결과를 유지한다.

## 3. 데이터 경계

- 서버 데이터는 React Query, 분석 직후 임시 데이터는 Zustand를 원본으로 둔다.
- view 내부 정규화 함수가 OpenAI의 최신 필드명과 기존 저장 JSON을 UI 타입으로 변환한다.
- 새 저장 데이터는 Group Atmosphere, Decision Making, Caution Point, Best Moment의 title과 description을 모두 보존한다.

## 4. UI와 접근성

- RoleCard는 onClick이 있을 때 semantic button과 명시적인 aria-label을 사용한다.
- PairCard도 상세 이동이 가능할 때 semantic button으로 렌더링한다.
- 모든 상세 화면은 뒤로가기 버튼, 데이터 없음 상태, 줄임 없는 본문을 제공한다.
- 주요 결과 카테고리는 32px, 역할 행은 18px 간격으로 정보 위계를 구분한다.
- 주의 포인트는 Caution 전용 WarningCard를 사용하고, 페어 상세의 두 인물 연결 표시는 중립적인 ×를 사용한다.
- 기존 390px 모바일 디자인 토큰, MBTI 기질 색상, 카드 간격을 유지한다.

## 5. 성능과 장애 대응

- 새 네트워크 요청은 추가하지 않고 기존 분석 상세 query 하나만 재사용한다.
- 임시 결과 상세는 Zustand에서 즉시 렌더링한다.
- 그래프 애니메이션은 CSS만 사용해 추가 렌더를 만들지 않고 800ms ease-out으로 실행한다.
- `prefers-reduced-motion` 환경에서는 애니메이션 시간을 사실상 제거한다.
- 정규화 함수는 불완전한 구버전 JSON을 안전하게 빈 값으로 처리한다.
- 단위 테스트로 최신/구버전 필드 변환과 설명 저장 보존을 검증하고, 브라우저에서 전체 흐름을 확인한다.

## 결과 저장 제목 입력 설계

### 1. 요구사항과 상태

- 임시 분석 결과의 저장 버튼을 누르면 제목 입력 바텀시트를 연다.
- 제목은 앞뒤 공백을 제거한 1~30자로 제한하며, 검증 문구는 한국어로 제공한다.
- 상태는 `closed → editing → submitting → success/error`로 전이한다. 저장 중에는 중복 제출과 닫기를 막고, 실패하면 입력값을 유지해 바로 재시도할 수 있게 한다.
- 저장된 DB 결과에서는 제목 입력을 다시 요구하지 않는다.

### 2. 런타임과 데이터 경계

- `ResultView`는 바텀시트 열림 여부와 서버 저장 상태를 관리한다.
- `SaveAnalysisSheet`는 React Hook Form과 Zod로 입력만 검증한 뒤 정리된 `title`을 `onSubmit`으로 전달한다.
- 실제 인증 확인, 저장 Server Action 호출, 성공 후 홈 이동은 view의 저장 핸들러가 담당한다.
- 제목은 서버에서도 동일한 Zod 스키마로 다시 검증해 클라이언트 검증 우회를 방지한다.
- 저장 성공 시 분석 목록 React Query 캐시를 무효화하고 임시 결과 세션을 비운 뒤 홈으로 이동한다.
- 홈과 테스트 기록은 그룹 유형보다 사용자가 입력한 `analyses.title`을 대표 제목으로 표시한다.

### 3. UI와 접근성

- 기존 `BottomSheet`, `TextField`, `Button`을 재사용해 390px 모바일 디자인과 터치 규격을 유지한다.
- 입력 필드는 명시적인 label, 오류 시 `aria-invalid`, 서버 오류는 `role="alert"`와 `aria-live`를 제공한다.
- 소프트 키보드의 완료 액션으로도 제출할 수 있도록 semantic form과 submit button을 사용한다.

### 4. 성능과 장애 대응

- 바텀시트는 결과 화면의 기존 클라이언트 경계 안에 두어 새 네트워크 요청이나 전역 상태를 추가하지 않는다.
- 제출 중 버튼을 비활성화하고 로딩 문구를 노출해 느린 네트워크에서도 진행 상태를 알 수 있게 한다.
- Server Action이 오류 결과를 반환하면 바텀시트를 유지하고, 예외가 발생해도 일반 재시도 문구로 복구한다.

### 5. 인증 왕복과 임시 저장

- 저장 제출 시 제목과 저장 요청 UUID를 `mingle:pending-analysis-save:v1` 세션 키에 `{ schemaVersion: 1, title, saveOperationId }` 구조로 보관한다. UUID는 새 저장을 시작할 때 한 번만 만들고 인증 왕복과 재시도 동안 유지한다.
- 비로그인 상태면 분석 결과와 제목을 유지한 채 `/signup?redirect=/result`로 이동하고, 인증 후 `/result`에 돌아오면 저장을 한 번만 자동 재개한다.
- 복귀 시 먼저 인증 상태를 확인한다. 로그인 사용자만 자동 저장하고, 비로그인 사용자는 제목이 채워진 바텀시트만 열어 회원가입 redirect 반복을 막는다.
- 자동 저장 중에도 제목 바텀시트를 열어 진행 상태를 보여주며, 실패하면 보존한 제목·요청 UUID·결과를 그대로 두어 사용자가 중복 생성 없이 즉시 재시도할 수 있게 한다.
- 저장 성공 시 pending title과 임시 분석 결과를 삭제하고 홈으로 이동한다. 저장하지 않고 결과·인증 흐름을 벗어나면 세션 매니저가 두 임시 데이터를 함께 삭제한다.
- 인증 확인 또는 Server Action 전송이 예외를 던져도 `finally`에서 저장 상태를 해제해 버튼이 영구 로딩 상태에 머무르지 않게 한다.
- 인증된 사용자는 브라우저의 세션 저장이 차단되어도 RPC 저장을 계속한다. 세션 저장 성공이 필수인 경우는 인증 화면으로 이동해야 하는 비로그인 사용자뿐이다.

### 6. 중복 저장 방지

- 제목을 처음 제출할 때 UUID operation ID를 한 번 생성하고 pending 저장 데이터와 인증 왕복 동안 그대로 유지한다.
- 게스트 결과 저장 Server Action은 제목과 operation ID를 모두 검증한 뒤 단일 RPC에 전달한다.
- `analyses.save_operation_id`는 직접 저장 흐름에 영향을 주지 않도록 nullable로 두고, `(user_id, save_operation_id)` unique 제약으로 사용자별 저장 요청을 멱등하게 만든다.
- RPC는 같은 operation ID가 이미 저장되어 있으면 기존 분석 ID를 반환한다. 동시 요청이 unique 제약에서 경합하면 현재 요청이 만든 그룹과 멤버를 subtransaction으로 롤백한 뒤 먼저 저장된 분석 ID를 반환한다.
